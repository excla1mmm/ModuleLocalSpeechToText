# Changelog

## Unreleased

- Housekeeping: removed the unused module-card images (about 188 KB) and 18 translation keys left over from earlier screens in all 29 catalogs; the retired transcript-event OpenAPI keys stay for cached documents. Removed the unreachable per-recording event feed reader (`GET /transcripts/events` has not been routed for a while) and updated the README: downstream modules import through `/call-transcripts/events`. The recording duration probe runs ffprobe under `nice -n 19` when `nice` is available, so it yields the CPU to Asterisk.
- Transcript page: the address now carries the moment being listened to. A turn click, a slider move or a pause adds the recording and second (`&lstt_stage=<result id>&lstt_t=<seconds>`), and switching to the internal-consultation tab adds `&lstt_leg=internal`. The parameters carry a module prefix so they never collide with Core or another module; links in the earlier unprefixed form (`stage`/`t`/`leg`) still open and are rewritten on the next address update. Another signed-in user who opens that address gets the same transcript with the right tab open, that recording held at that moment (playback starts on Play, as browsers require) and the turn scrolled into view. The call-history modal never changes its page address.
- Storage: the module database is about three times smaller. Call transcript revision payloads no longer store data that every reader rebuilds from the raw segments (`turns`, `turn_count`, `text`) or never reads (per-segment `normalized_text`, `recording_fingerprint`, `resolution_status`, `source_index`), and are written deflated (`z1:` prefix, `CallTranscriptPayloadCodec`); legacy plain-JSON payloads stay readable. Call transcript parts no longer duplicate their segments (`segments_json` is `[]`); they are read from the `m_STTResult` row, which is only rewritten together with a new current part. The API responses, `content_hash`, `parts_hash`, `segment_id` values and revision numbers are unchanged, so nothing is re-published. Upgrade: new schema migration 18 rewrites existing revision/pending payloads and releases part copies that are identical to their result (differing or unreadable rows are left as they are; re-running is a no-op). Setup then switches the database to incremental auto-vacuum with a one-time `VACUUM` (postponed with a warning when the disk lacks about twice the database size), and the retention sweep returns freed pages to the file system. On a production copy: 114 MB → 38 MB, migration 0.8 s, no difference in any of 2 866 projected transcripts/parts.
- Call-transcript API: the call transcript detail now reports `language`, the ISO 639 code the worker reported for every part of the call (`null` when unknown or when parts are in different languages), so downstream analysis can answer in the language of the conversation. It is derived from the part results on each request, not stored in the revision payload, so existing revisions keep their `content_hash` and nothing is re-published or re-analyzed. No migration.
- Call-transcript API: deletions now reach downstream importers. Deleting a transcript in the UI, or purging it by the retention period, publishes a `call-transcript.deleted` tombstone (`aggregate_id`, last `revision`, `deleted_at`, `deletion_reason` `manual`/`retention`) into the call-transcript event feed. Tombstones are served only when the consumer passes `include_deleted=true`; the default feed is unchanged, so importers that accept only completed/updated events (current ModuleAISupervisor) keep working. Tombstones are written in the deleting transaction after the pre-deletion cursor frontier, so they are never skipped by a stored cursor, and are pruned after 90 days. The event list and call transcript detail now report `contract_version: 2`, so consumers can detect this contract instead of comparing module versions. No database migration: tombstones reuse the existing `m_STTCallTranscriptEvent` columns, and an older build ignores them (its feed joins on the deleted aggregate).
- Label the employee side of a transcript with that employee's PBX name (user name, then extension caller ID) instead of the generic "Employee" in the conversation legend, speaker filter and every turn, in both the transcript page and the call-history modal. An employee without a name keeps the "Employee" label, and the client side is never renamed.
- Fixed the Transcripts tab (and its full-text search) always rendering "no transcripts" even with a database full of them. The candidate query's date pre-filter compared an affinity-less SQLite `CASE` expression against date bounds that PDO binds as text, so SQLite compared storage classes instead of numbers and matched nothing; since the date filter defaults to the last seven days, it was always active. The effective-time expression is now wrapped in `CAST(... AS INTEGER)`, giving it the numeric affinity that makes SQLite coerce the bound values.
- Upgrade: new schema migration 17 restores the two partial unique indexes that model annotations cannot express (one current part per call transcript/result, one v2 worker per API key). Installs from earlier builds created them under names Core's boot-time annotation pass drops, so the invariants could silently disappear. Rows that slipped in meanwhile are repaired first: older duplicate "current" parts are demoted (never deleted), and a v2 API key shared by several workers stays with the most recently seen one. On Core 2026.1+ setup now also runs Core's own module annotation pass (preserving module-added columns, like boot does) under the setup snapshot, so the one-time `text`->`string` rebuild of the call-transcript tables happens during install instead of at the next boot, and the partial indexes are re-ensured right after it.
- Security: all state-changing administration actions (save settings, save model, retry failed jobs, download worker installer, generate/delete worker API key, delete transcript) now require both a POST request and a same-origin `Origin`/`Referer` header, closing a CSRF gap where these were reachable via a plain GET/cross-site request.
- Security: `WorkerRequestContext::isAdministrator()` now fails closed for any auth type it cannot unambiguously identify as an administrator. An empty auth type (Core's `SecurityType::LOCALHOST`, which never populates `sessionContext`) is still treated as administrator, matching Core's own `GetSearchItemsAction::getUserRole()` convention; a session-backed `bearer_token` (JWT) is only granted admin when the underlying session's role is Core's `admins` role, matching the web UI's own check; any other auth type - including the `session` constant Core uses elsewhere, which this module's REST layer never actually emits - fails closed.
- Security: the `CallTranscripts`, `Transcripts`, and `CallTranscriptEvents` read REST APIs now map only their dedicated not-found exception to 404 with a fixed message; any other failure returns a generic 500 with the exception logged server-side (sanitized), instead of leaking `$exception->getMessage()` to the client. `Unknown action` responses now also set `httpCode` 400.
- Bulk "retry failed jobs" no longer requeues jobs that ended in a deterministic, non-retryable terminal failure (recording file missing, duration too long, file too large, result persistence failed); those still show up in the queue's error list and remain individually retryable by an administrator.
- `POST /jobs` (job creation) and the worker recording-download path now share one `RecordingPathGuard` implementation for validating `file_path`/serving path against the monitor directory, instead of two slightly different inline checks.
- Removed a side effect from job-lease validation: `STTJob::requeueStaleProcessing()` is no longer called from inside `validateAssignedJob()`; stale-lease recovery is the scan cycle's job.
- Worker job claiming is now FIFO within a priority band (oldest call/job first) instead of LIFO (newest first), so an old or recovered pending job is no longer starved by a steady stream of new jobs at the same priority.
- `STTJob`'s relation to its assigned `STTWorker` is now declared as `belongsTo()` instead of `hasOne()`, matching the actual many-jobs-to-one-worker relationship.
- Flash messages for failed queue retry / worker API key create / worker API key delete no longer show the raw internal exception message; they show a translated generic "operation failed" message instead (new `module_local_speech_to_text_OperationFailedError` key, all locales).
- Replaced `@`-suppressed filesystem/process calls (`rename`, `unlink`, `mkdir`, `proc_open`, `proc_terminate`) across the log journal, legacy log migration, and setup cleanup code with an explicit, scoped-error-handler helper (`QuietOperation`) so the same best-effort behavior no longer relies on the `@` operator.
- Renamed the tracked `readme.ru.md` to `README.ru.md` (case-only rename) and untracked the `.superpowers/` agent working directory (added to `.gitignore` along with `.worktrees/`).
- `GET/PATCH /jobs` no longer leaks the internal `[terminal] ` bookkeeping marker (used by bulk-retry to skip deterministic terminal failures) in `error_msg`; the REST payload also now exposes a `terminal_error` boolean. The strip/detect logic is now a single `STTJob::displayErrorMessage()`/`isTerminalErrorMessage()` pair shared by `STTJobManagementService::format()` and the administration queue view, instead of being duplicated.
- Reformatted the one-line "minified" `Jobs`/`JobFailures`/`JobResults` REST processors, controllers, data structures, and `STTJobManagementService` into normal multi-line PSR-12-style code (whitespace/line-break only; verified token-for-token identical to the prior source, aside from splitting grouped `use {...}` imports into one `use` per line).
- Extracted `LocalSpeechToTextMain` (1120 -> 845 lines) into three focused collaborators: `JobApiResponseBuilder` (success/error/file/ownership-conflict response building), `WorkerAuthorizationValidator` (worker identity, API-key binding, and job-lease ownership checks), and `JobResultPayloadNormalizer` (transcript/technical-info encoding and quality-stat merging). All public method signatures on `LocalSpeechToTextMain` are unchanged; `safeRecordingPath()`/`fileWithinSizeLimit()`/`fileResponse()` stay on `LocalSpeechToTextMain` as thin wrappers since they are exercised directly via reflection in tests.
- Extracted `WorkerLocalSpeechToTextJobs` (1633 -> 599 lines) into five focused `Lib/Services` collaborators: `CdrRecordEvaluator` (per-record identity/eligibility/duration decisions and job creation), `RecordingRetryCache` (delayed/skipped display-cache storage backed by `RetryStateStore`), `CdrDiscoveryScanner` (the id-watermark realtime scan, its legacy-cursor migration, and the one-shot backfill scan), `RecordingRetryProcessor` (delayed/skipped retry-due processing), and `TranscriptRetentionCoordinator` (the throttled retention purge sweep). All moved method bodies are unchanged apart from the mechanical `$this->x()` -> `$this->evaluator->x()`/`$this->retryCache->x()` redirections and threading the worker's live `needRestart`/iteration-budget flags through as closures; the worker keeps the process lifecycle (`start()`, the main loop, signal/process-guard handling, and iteration budget) and thin forwarders for every method still exercised by name via reflection in tests.
- Fixed short calls whose transcript is legitimately empty (every segment rejected by the quality filter, or the worker sent none) being retried and re-transcribed up to 3 times and then silently failing with a misleading "lease timeout" error. `STTResult` and `STTCallTranscript` now explicitly allow their legitimately-empty hash/search columns, so an empty transcript saves and completes normally (with a completion event and a call-transcript revision) instead of hitting Phalcon's automatic not-null validation. A worker-submitted result that still fails to persist for a genuine, deterministic reason now moves the job straight to a terminal error state with an accurate error message and a `queue.job_failed` log event instead of returning a retryable 500 the worker loops on. `api.operation_failed` log entries now include the sanitized exception message and job_id, not just the exception class name.
- Added one persistent source-instance identity to the Local STT database and to call event/detail responses, including empty event pages.
- Normal in-place upgrades preserve the identity. A clean database creates a different identity so source-local aggregate, result, job, revision, and cursor values cannot collide across installations.
- Ordinary coordinated upgrades are zero-touch in either order. Install the source-aware AI Supervisor build before intentionally deleting an old Local STT database; a clean reset is not safe while AI Supervisor 1.73 remains installed.
- AI Supervisor can preserve existing results for unchanged `call_id + content_hash` calls and automatically queue changed or uncertain content without adding an administrator action.
- Settings tab: numeric fields (poll interval, max recording duration, CDR scan limit, processing timeout) now render as narrow inline inputs with the label beside them, instead of full-width fields stacked above their labels.
- Settings tab: the CDR history and transcript retention sliders now inset their track from the segment edges, so the first and last tick labels no longer touch the box border.
- Workers tab: removed the "Worker update instructions" link and its translation key; it pointed at a fixed docs URL with no per-worker context.
- Removed four technical settings from the Settings tab and replaced them with fixed internal policies: CDR discovery now backs off adaptively from 15 to 30, 60, 120, and 180 seconds while idle (resetting to 15 seconds on any activity), housekeeping keeps running every 15 seconds regardless; a discovery pass reads at most 30 CDR rows; the processing job lease is now a fixed 600 seconds with unlimited heartbeat renewal; the recognizable recording duration hard limit is now a fixed 180 minutes (10800 seconds). Existing `poll_interval_sec`, `max_recording_duration_min`, `cdr_scan_limit`, and `processing_timeout_sec` rows are left untouched in the database as inert legacy data.
